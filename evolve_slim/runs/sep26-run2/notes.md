# sep26-run2 notes

**Summary.** Best kept: `v34_gemm` (slim_lib/v34_gemm.py): mean_regret -0.00169 (baseline pyfasterrisk_v1 0.00269), geo_mean_time 0.037 s (baseline 1.469 s, 40x faster), mean_test_auc 0.8424 (baseline 0.8406), n_invalid 0. `v35_scratch` (the final slim.py) has the same points on the suite plus time-limit deadlines for larger held-out data. The loss gains came from scoring with the harness's calibrated loss (integer local search, rounding choice); the speed gains came from grouping rows by support pattern, fitting beam children from sparse column counts, and batching mat-vecs into BLAS mat-mats. Random-restart checks suggest the remaining headroom on this suite is about 0.0001 mean loss.

Setup: evaluate.py resolves data via the run folder (src symlink path), so a symlink `data -> ../../data` was added to the run folder so the harness can load the suite. Helpers: setstatus.py (set keep/discard), cmp.py (per-problem regret/time), prof2.py (cProfile after a warm-up fit).

## Profile of the starting solver (pyfasterrisk_v1)
bank k=10 (19.9 s): finetune/step_coord 82% (dense exp over all n rows per coordinate step, 445k calls); beam search 48%, diverse pool 38%, star-ray sequential rounding 14%.
spambase k=5 (2.5 s): beam search 90% (again finetune). Regret: 91% of mean_regret comes from spambase (continuous features, CapitalRunLength* at large scale round to 0: k=3 returns 2 nonzeros).

## Attempts
- pyfasterrisk_v1 (baseline): regret 0.00269, time 1.469 s, AUC 0.8406. keep (baseline).
- v2_numba: FasterRisk ported to numba on unique (x, y) rows with sparse columns; finetune = projected Newton on (intercept, support) instead of coordinate descent (CD needed ~100 sweeps on correlated one-hot columns); final pick by calibrated loss. regret 0.00220, time 0.296 s, AUC 0.8414. keep (5x faster, slightly lower loss).
- v3_ils: + best-improvement integer local search (value change / add / swap moves) from the 5 best rounded pool solutions. Moves ranked by an incremental estimate (exact loss at current (a, b) minus a trust-region Newton step in (a, b), computed only on the rows the move touches), top 6 checked exactly. regret -0.00106, time 0.540 s, AUC 0.8415. discard by the rule (time +82%), but the regret drop is large (spambase regret 0.022 -> -0.009; spambase k=3 beats best known). Without the trust region the Newton estimate diverged and no move was found.
- v4_binned: ILS moves evaluated on cells (score bin, value of x_j) instead of rows: for integer-valued data the score takes few values, so a column costs nnz integer adds + ~100 exps per delta. ILS on fico 4.8 s -> 0.2 s. Same losses. regret -0.00106, time 0.367 s. discard (time +24% vs v2).
- v5_nopool: drop the diverse pool; star-ray + ILS start from the 10 final beam parents. regret -0.00124, time 0.264 s, AUC 0.8427. keep (ILS replaces the pool's diversity; more distinct supports as starts).
- v6_screen: beam children ranked after fitting only the new coordinate (+ intercept step), only the best parent_size children finetuned. regret -0.00022, time 0.195 s. discard (regret +0.001: australian, fico, magic worse; the one-coordinate loss ranks children badly).
- v7_groups: exact speedup of the beam: each beam node keeps the rows grouped by (y, x_support) (refined per child by one column's value codes via a dense table), and Newton finetune + star-ray run on groups (<= 450 groups instead of 10k rows for binary data at k=10). Same solutions as v5. regret -0.00123, time 0.107 s, AUC 0.8427. keep (2.5x faster).
- v8_rawscreen: in ILS, columns with >32 distinct values ('raw', only spambase) are screened by a second-order model at fixed (a, b) (no exp) and only the best 8 fully evaluated; also a JIT warm-up at import that exercises the continuous-column paths (the harness warm-up is binary only, so kernels used only by continuous data were compiled inside timed spambase fits). regret -0.00117, time 0.104 s. discard (spambase k=3/5 found worse local optima; overall time -3%).

- v10_fastdata: Data built by a numba column pass (binary fast path, CSC, value codes) and row dedupe by a random projection hash instead of np.unique(axis=0). Same losses. regret -0.00124, time 0.103 s. discard (-4% only), carried into v12.

- v14_numbachild: v10+v11+v12+v13 plus child creation (regroup + design + Newton) in one numba call instead of ~20 numpy calls per child (Python overhead dominated small problems). regret -0.00122, time 0.071 s, AUC 0.8428. keep (-34% time vs v7, regret +0.00001).
